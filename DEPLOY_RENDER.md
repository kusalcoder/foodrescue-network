# Deploy FoodRescue Network on Render

This deployment uses one Render web service and one managed Render PostgreSQL database. The local PC is not part of the runtime path.

## Deploy

1. Push the `foodrescue_network` folder to a private or public GitHub repository.
2. In Render, choose **New > Blueprint** and connect the repository.
3. Select `render.yaml` and apply it.
4. Render creates the web service, PostgreSQL database, HTTPS URL, and generated `SECRET_KEY`.
5. Wait for the `/api/health` health check to become healthy.
6. Open the web service's `https://...onrender.com/` URL from a phone, desktop, or mobile data connection.

## Required production environment variables

The Blueprint supplies these automatically:

- `FLASK_ENV=production`
- `SECRET_KEY` (generated by Render)
- `DATABASE_URL` (from the managed PostgreSQL database)
- `UPLOAD_FOLDER=uploads`
- `MAX_FILE_SIZE=5242880`

Do not upload `.env` or put real secrets in Git.

## Build and start commands

```text
pip install -r requirements.txt
python scripts/ensure_db.py && gunicorn --bind 0.0.0.0:$PORT run:app
```

`ensure_db.py` creates missing tables in the new managed database. The existing local PostgreSQL database is not used by the cloud service.

## Verification

After deployment, check:

- `/`
- `/register`
- `/login`
- `/api/health`
- `/favicon.ico`

Then exercise registration, login, `/api/profile`, provider listings, recipient requests, pickups, notifications, and admin reports using cloud-created accounts.
